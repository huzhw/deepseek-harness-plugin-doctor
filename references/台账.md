## 修复案例

### 案例1（2026-09-12）store 漂移 —— safe profile 起不来

- **症状**：DSH 启动失败，前台报 `INTERNAL_PLUGIN_INSTALL_FAILED: PREINSTALL_FAILED` + `ERR_PNPM_UNEXPECTED_STORE Unexpected store location`，指名 `profiles\safe`
- **根因**：用户级 `~\.npmrc` 加了 `store-dir=F:\Program Files (x86)\pnpm-store`（全局挪 F 盘），而 safe profile 的 `.npmrc` 没钉 store-dir；safe 的 `node_modules\.modules.yaml` 记录的是 `C:\Users\Administrator\AppData\Local\pnpm\store\v10`，pnpm 解析到 F 盘与记录不符即炸
- **背景**：web profile 同病已于 2026-09-10 修过（.npmrc 钉死），safe 漏钉
- **修法**：`profiles\safe\.npmrc` 补两行（与 web 同构）：`store-dir=C:\Users\Administrator\AppData\Local\pnpm\store` + `@deepseek-ai:registry=https://mirrors.cloud.tencent.com/npm/`
- **验证**：`pnpm -C safe store path` 回到 C 盘 v10；`pnpm -C safe install --frozen-lockfile` 478ms 零下载完成；重启后 `dsh-tauri-pet`、`dsh-tauri-turnrewind` 自动补装成功

### 案例2（2026-09-12）externals 漂移 —— web profile 页面 Failed to load plugins

- **症状**：进程活着、HTTP 正常、健康检查 74/74 通过（**假阳性**），浏览器渲染 "Failed to load plugins"，console：`failed to import loader entry 05381d36 (dsh-permission-rules): client-modules: require("process") missed the module table`
- **根因**：dsh-permission-rules 0.7.1（当天 10:12 发布、12:24 被 app 刷上）打包时把内置依赖 yaml@2.9.0 的 `process`、`buffer` 外置；dsh client-modules 运行时模块表无此种子。新旧核心运行时文件逐字一致 → 锅在插件构建，非核心回归
- **侦查法**：`npm pack dsh-permission-rules@0.6.21` 解包 grep 对比——0.6.21 的 client.js `require("process")` 为 0 处，0.7.1 为 3 处；0.6.21 peer 依赖声明兼容 `>=0.1.5-alpha.1`，回滚备选成立
- **修法**（`profiles\web\node_modules\dsh-permission-rules\lib\client.js` 共 4 处垫片，备份在 `profiles\web\.bak\dsh-permission-rules-0.7.1-client.js.bak`）：
  - 3 处 `require("process")` → `(globalThis.process ?? {env:{},emitWarning:function(){}})`（yaml 实际只用 `env.LOG_STREAM`/`env.LOG_TOKENS`/`emitWarning`，全覆盖）
  - 1 处 `var node_buffer = require("buffer");` → `var node_buffer = { Buffer: globalThis.Buffer };`（yaml binary 标签有 typeof 守卫，自动走 atob/btoa）
- **验证**：浏览器刷新后完整 UI 渲染、console 零报错（loader entry 哈希 05381d36 → ea876926 → 新值，证明服务端现读磁盘、补丁免重启生效）
